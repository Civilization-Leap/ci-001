## DOI release sequence

Zenodo can reserve a DOI before publication. Enablement of a GitHub repository
and automatic ingestion of new releases are separate account steps. Do not
assume an automatic import uses a manually reserved DOI without verification.

For the first release, choose one archive path and avoid duplicate independent
Zenodo deposits for the same version. If using a reserved DOI, bind it into the
forms, README, CITATION.cff and release metadata before finalizing and hashing
the assets. Check the Zenodo/GitHub integration against the actual account and
its record metadata before publishing tag v1.4. If the integration cannot reuse
that reservation, use the reserved manual deposit for v1.4 and explicitly link
the GitHub release; configure later automation without pretending a shared
version family already exists.

A reservation is not a resolving published DOI. Completion requires an actual
public record, verified files/license/version, and a resolving DOI. Do not move
an already published v1.4 tag just to insert its DOI. Correct metadata through
the supported record process; asset changes require a new disclosed version.

Official guidance: [reserve DOI](https://help.zenodo.org/docs/deposit/describe-records/reserve-doi/),
[enable repository](https://help.zenodo.org/docs/github/enable-repository/),
[archive releases](https://help.zenodo.org/docs/github/archive-software/).
