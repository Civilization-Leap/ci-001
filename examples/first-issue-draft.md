# [Applicability] E for public archives: stopping future release versus recalling existing copies

**Status: maintainer-prepared issue draft, not submitted, not external adoption.**
Prepared with ChatGPT assistance on 2026-09-08. This reports a real publication
preparation problem and an unresolved scope question; it is not a completed
audit of GitHub or Zenodo and does not invent a system operator's evidence.

System: the CI-001 V1.4 file-release preparation process. Evidence: the original
verification manifest includes the current M1 master, while the intended public
repository excludes publication masters. This conflict was found before upload;
the candidate now uses an explicitly scoped subset (provenance/manifest.json).

Affected party: author/rightsholder. Capacity under review: correct or withdraw
the intended file selection before the first public upload. The original file
list, exact original files and separate candidate are available locally. The
candidate selection was changed without modifying the original audit archive.
This supplies evidence about a pre-publication correction path, not a permanent
right to recall copies already received by others. Formal C/E/R states remain
unassigned pending a recorded authorization/response path and time window.

Clause: §2.1 E and its relation to §1.1's definition of the assessed capacity.
Question: when applying CI-001 to publication infrastructure, how should a form
distinguish stopping a future disclosure from recalling a prior public copy?
Changing one capacity into the other midway would silently change the assessment.

Proposed clarification: require an explicit disclosure event in A5 and separate
records for pre-publication withdrawal and any claimed post-publication recall.
Neither platform deletion nor removal of a web link alone establishes recall.
Do not infer total irreversible closure from a single failed recall path without
checking C, E, R, §2.4 and the same capacity/window.

Safeguards: preserve §3.3, §4.1 and §4.2; any publication restriction must record
scope, review, correction and release conditions. No destructive real publication
test should be used merely to prove that disclosure cannot be undone.

中文题目：公开存档的退出，如何区分“停止后续公开”与“召回已经取得的副本”？
