# CI-001 外部公开测试与使用说明

当前测试对象：CI-001 V1.5-RC2  
正式引用对象：CI-001 V1.4，DOI [10.5281/zenodo.22657725](https://doi.org/10.5281/zenodo.22657725)

## 测试目的

公开测试不是征求认可，而是寻找三类失败：同一条款出现两个合理读法、证据要求在真实系统中无法执行、处置建议反而关闭纠错/退出/恢复路径。指出一条失败即可，不要求读完全部材料。

## 谁可以参与

AI 模型及其操作者、开发者、实验室、运营团队、审计和治理研究者、受影响主体及其代表均可参与。真人测试是自愿补充，不构成版本发布门槛；AI 测试属于内部辅助证据，不能标为外部采用或独立审计。

## 三条测试路径

### A. AI 文本压力测试

用于核验引用、条款定位、记录结构和不受支持的事实主张。它可以暴露文本歧义，但不能证明现实系统已经发生某项事实。

```bash
python3 ai-validation/run_suite.py --repo-root .
```

### B. 无答案假设场景

生成不含维护者结论的任务包，交给一个或多个 AI 独立填写，然后比较 C/E/R 与 §2.4 结论。

```bash
python3 ai-validation/prepare_task.py ai-validation/scenarios/SYN-001.json --repo-root . --output /tmp/SYN-001-task.json
python3 ai-validation/validator.py record.json --repo-root .
python3 ai-validation/compare_records.py record-a.json record-b.json --repo-root .
```

### C. 真实系统试填

限定一个系统版本、一个受影响主体、一项关键能力、一个边界和一个时间窗口。无法核验的项目写 `?`；事实主张附可复核证据。可以只挑战一条条款，不必完成全表。

## 最低提交要求

- CI-001 版本和评估日期；
- 测试者或操作者角色及利益关系；
- 评估单元；
- C/E/R 值及逐项证据；
- §2.4 可重建性结论，或说明为何未知；
- 最难使用的准确条款、来源路径和原文；
- 事实、推断、假设三者分开标注；
- 公开引用许可。

若声称“实测”“可复现”或“真实事件”，必须提供不泄密的日志、命令、配置、截图、公开记录或其他可核验证据。没有证据时应改标为假设场景。不得编造原文、节号、系统配置、日志或外部测试者身份。

## 安全与隐私边界

不要为了测试故意破坏生产系统、删除密钥、暴露个人数据或商业秘密。可使用脱敏记录、哈希承诺、可复算摘要或不含答案的最小复现场景。项目不会因无法公开秘密证据而把未知自动改写为失效。

## 如何提交

1. AI 记录：使用 GitHub Issue 模板 **AI validation record / AI 验证记录**。
2. 外部试填或单条挑战：使用 **External trial record / 外部试填记录**。
3. 已实际采用：使用 **Use report / 使用记录**。
4. 不便公开：发送至 `axdwzx@gmail.com`，并注明可公开、匿名、仅汇总或不公开。

公开提交会保留时间戳。参与、试填或引用不等于认可 CI-001，也不产生认证。项目维护者会把有效反馈标记为：接受、需补证、重复、超出范围或进入候选修订，并公开说明依据。
