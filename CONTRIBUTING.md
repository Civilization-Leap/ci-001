# Report a use, a failure or an alternative

Use either language. No institutional affiliation, prior agreement with the
source theory or complete audit is required. A partial attempt with a precisely
identified failure is useful. Do not publish passwords, personal data or a live
system's destructive instructions; a redacted record or safe test is sufficient.

For a practical objection provide: system type/version, affected party and
capacity, phase/time/window, the exact clause, observed evidence, why the rule
cannot be applied, and a proposed alternative if you have one. Unknown is a valid
result. Upload a completed one-page form when useful; it is not mandatory.

Maintainers record the objection and evidence, distinguish fact from inference,
test changes safely, and publish the disposition: accepted, corrected, disputed,
or insufficient evidence, with reasons and an opportunity to reopen. Reasoned
disagreement does not justify deleting a report. An AI-written maintainer example
must identify itself and must never be counted as independent external adoption.

An actual external application is evidenced by a concrete system assessment or
a traceable integration into another framework. Stars, views, downloads, a blank
issue, or a maintainer example do not demonstrate that outcome. Renamed or
unattributed use can still be recognized when reliable evidence establishes use;
this measurement rule does not waive CC BY attribution obligations.

## Bilingual changes

One repository, docs/zh and docs/en; a shared evidence set. Chinese controls an
interpretive conflict pending correction. For each substantive change, provide
Chinese and English together, a semantic summary, clause mapping and evidence.
Untranslated proposals remain proposals and must not silently become a release.
Section §8 records source reasoning; observed failure can require revisiting it.
Source-text amendments use the books' own review and publication tracks.

Maintain the human-readable change rationale. Git diff shows the edited text,
not why a judgment changed; DOCX binary changes alone are inadequate. Do not
erase prior versions or retroactively invent release dates or review outcomes.
